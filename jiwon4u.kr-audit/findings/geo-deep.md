### 1-3. 가장 좋은 문단 (p18, "Claude Code에서는 어느 쪽 요금이 나가나요?")

> "Claude Code는 구독으로도, API 키로도 쓸 수 있어요. 구독으로 로그인하면 채팅과 같은 한도를 나눠 쓰고, Console 계정이나 API 키로 쓰면 쓴 만큼 결제돼요. … 컴퓨터에 ANTHROPIC_API_KEY 환경변수가 설정돼 있으면, Claude Code가 구독 대신 그 API 키를 써요. 공식 안내에도 구독이 아니라 API 사용 요금이 청구된다고 나와 있어요."

좋은 이유는 네 가지입니다. ① 질문형 H2 바로 아래에서 첫 문장이 답이고, ② 고유 명사(ANTHROPIC_API_KEY, /status, /cost, /login)가 구체적이며, ③ 공식 출처를 언급하고, ④ 뒤 문단에 "3일 만에 40만 원" 같은 직접 경험(E-E-A-T의 Experience)이 붙어 있습니다. 같은 글의 Sonnet 토큰 비용 계산 예시(0.034달러, 30편에 약 1달러)도 AI가 그대로 인용하기 좋은 "계산된 수치"입니다.

### 1-4. 가장 약한 문단 (p16, 첫 H2 아래)

> "프롬프트는 AI에게 일을 시키려고 입력하는 지시문이에요. 같은 문장이어도 모델이 달라지면 해석과 출력 방식이 달라질 수 있어요."

약한 이유는 네 가지입니다. ① 22어절에 그쳐 근거가 없고, ② "~수 있어요"처럼 단정하지 않는 표현만 있으며, ③ 이 글만의 정보(지원포유가 세 AI에 실제로 같은 지시문을 넣은 결과)가 문단에 들어 있지 않고, ④ 핵심 근거가 아래 목록과 스크린샷으로 흩어져 있어 문단만 떼어 내면 의미가 없습니다.

**고쳐 쓴 예 (약 55어절, 기준일·직접 테스트·수치 포함)**

> 같은 프롬프트를 클로드, 제미나이, 챗GPT에 넣어도 답은 같지 않아요. 지원포유가 2026년 10월 9일 같은 일정 조율 메일 지시문을 세 서비스에 넣어 보니 분량, 표 사용 여부, 말투가 모두 달랐어요(아래 화면 참고). 이유는 세 가지예요. 모델마다 기본 형식 선호가 다르고, 지시가 모호하면 빈칸을 서로 다르게 채우며, 요금제에 따라 한 번에 기억하는 양(컨텍스트)이 달라요. 그래서 역할·목적·자료·형식·제약 5가지를 고정한 공통 틀을 쓰면 편차가 줄어요.

(실제 글자 수나 표 개수를 쟀다면 "클로드 약 OOO자, 제미나이 표 2개"처럼 숫자를 넣는 것이 가장 강력합니다. 직접 잰 값만 쓰세요.)

### 1-5. p21 정의 문단 보강 예 (용어 사전 글이 정의형 질의의 1순위 인용 대상이므로)

현재 정의에는 "누가, 언제" 정보가 없습니다. 고쳐 쓴 예입니다.

> MCP(Model Context Protocol)는 Anthropic이 2024년 11월 공개한 오픈 표준으로, AI가 구글 드라이브·캘린더·노션 같은 외부 도구와 데이터에 같은 방식으로 연결되도록 정한 규칙이에요. 연결을 제공하는 쪽을 MCP 서버, 이를 쓰는 앱(클로드 등)을 MCP 클라이언트라고 불러요. 한 번 만든 MCP 서버는 이 규칙을 지원하는 여러 AI 앱에서 다시 쓸 수 있어요.

그리고 용어표 26개는 `DefinedTermSet` + `DefinedTerm` JSON-LD로 감싸면 정의형 질의("토큰 뜻", "양자화 뜻")에서 추출 정확도가 올라갑니다.

### 1-6. 문단 작성 규칙 제안 (원고 프롬프트 규칙 15가지에 추가)

1. H2 아래 첫 문단은 35–60어절로 씁니다. 첫 문장은 "X는 Y예요" 같은 정의 또는 결론으로 시작하고, 수치 1개와 기준일 또는 출처 1개를 넣습니다.
2. 목록은 첫 문단 **뒤**에 둡니다. 목록 항목만으로 답이 완성되게 쓰지 않습니다.
3. "~수 있어요"는 한 문단에 한 번까지만 씁니다. 공식 문서가 단정하는 내용은 단정하고 출처를 붙입니다.
4. FAQ 답변은 2–3문장으로 쓰고, 첫 문장을 답, 둘째 문장을 근거(기준일·출처), 셋째 문장을 예외로 구성합니다.

### 구체적 제안

**(1) 이름 규칙을 하나로 정하기**
- 표기 원칙: 한글 "지원포유", 영문 "Jiwon4U"(대소문자 고정), 핸들 `jiwon4u`.
- 사이트명은 "지원포유 (Jiwon4U)", 부제는 "클로드 활용 가이드"로 나눕니다. og:site_name과 publisher.name에서 " - 클로드 활용 가이드"를 빼야 엔터티 이름이 깨끗해집니다.
- X 핸들이 본인 것이라면 `jiwon4u`로 바꾸거나 sameAs에 넣습니다. 아니라면 About에 "공식 채널은 아래뿐"이라고 명시합니다.

**(2) About 페이지 손보기** (Blogger 페이지 편집 화면에서)
- 페이지 제목을 "지원포유(Jiwon4U) 소개: 클로드를 직접 써 보고 기록하는 블로그"로 바꿔 title "Latest Posts" 문제를 해결합니다(테마의 page title 조건문도 점검).
- 첫 문단을 정의 문장으로 씁니다. 예: "지원포유(Jiwon4U)는 1인 운영자가 2026년부터 Anthropic의 Claude를 직접 써 보며 사용법·요금·자동화 경험을 한국어로 기록하는 블로그입니다."
- 추가할 내용: 운영 시작일, 사용 중인 플랜(Pro→Max, p08에 나온 경험), 직접 만든 도구('지원포유 콘텐츠 스튜디오'), 검수 절차(p20 링크), 정정 정책("오류 제보 후 48시간 안에 수정하고 수정 이력을 표기"), 공식 채널 목록.
